FilterTube Feature Guide

Start here for the main filtering, focus, migration, and YouTube behavior controls. Use the detailed Help sections below whenever you need the full behavior or safety boundary.

Self-Control Sessions and time limits for every profile
Any profile can have its own daily YouTube allowance. The popup shows the remaining daily time, and an exhausted profile receives the full-page serene pause screen. Separately, Settings now offers a Self-Control Session that pins the active profile and freezes its current filters until a non-cancellable countdown ends.
Blocked and Always allowed rule collections
Main YouTube and YouTube Kids each keep independent Blocked and Allowed rule collections. Opening a collection only chooses which saved rules you are editing; it does not change the active Blocklist or Whitelist mode. Quick additions in the popup follow the active mode, while advanced exceptions stay in the full Filters page.
Direct-access and description checks
Blocked Watch, Shorts, channel, playlist/autoplay, and embedded-player routes cannot bypass the active rules. FilterTube reuses YouTube's loaded Player response and visible Watch description before considering another metadata lookup, so ordinary blocklist playback is not held merely because a complete description is still missing. Allow-only mode remains safer and waits when identity is required.
Send adverts to The Void
This default-on control applies on YouTube Main and YouTube Kids in both Blocklist and Whitelist modes. You can still turn it off. FilterTube first removes the observed advert plan from YouTube's existing Player response so pre-roll, mid-roll, and post-roll adverts are not scheduled. It does not create extra YouTube API traffic. If an advert still escapes into the player, FilterTube hides it without showing an intermediate banner, silences it, and advances only positively identified advert media. Watch-player ownership, duration matching, and a last-moment media check prevent recommendation previews or the requested video from being advanced. For troubleshooting, open DevTools Console, filter for [FilterTube][Advert Void], or inspect the latest 100 structured events in window.__filtertubeAdVoidLog. player-ad-plan-removed confirms prevention; fallback interruptions receive numbered sessions and placement, while ad-ended and requested-content-ready separate advert cleanup from YouTube's following video load.
Safer complete BlockTube migration
Large BlockTube JSON exports are previewed, capacity-checked, applied transactionally, read back, and summarized with an apply receipt. A failed write rolls the import back instead of reporting false success. Imported JavaScript is never executed, the BlockTube UI password never becomes a FilterTube PIN, and importing rules does not replace the FilterTube theme.
Official category filtering
Category Filters now use YouTube's official video category, have their own independent Block/Allow-only mode, appear below Core in full Content Controls, and are also available in the popup. Nearby uncached cards are checked in small bounded batches so FilterTube does not continuously request metadata.
Spoken-language filtering (Experimental)
Language Filters prefer YouTube's original/default spoken-audio evidence. Auto-dubbed alternatives do not change the source language. For captionless videos, FilterTube can use strong writing-system evidence from creator-supplied Player metadata; weak or ambiguous text remains unknown. Category and language checks share one paced Player-metadata request and one cache entry per video.
Always use original audio (Experimental)
This separate Player control changes only the currently playing video's audio track. It reuses YouTube's loaded Player response and in-page player API to prefer a proven original track over an automatic dub. It makes no extra request, never delays playback, and leaves the current audio unchanged when the original cannot be proven.
Current Watch, Mix, comments, and YouTube layouts
Current camelCase video lockups and Watch recommendations are recognized without treating comments, navigation chips, or Mix queue rows as ordinary category-owned videos. A Mix discovery card can use its seed video's identity, including for faster 3-dot channel actions, without copying that identity to every queue item.

Category Filters Are Working

Category Filters use the official category supplied by YouTube for each video. Open Content Controls, find the Category Filters card directly below Core, choose categories, select a mode, and turn the filter on. The same controls are also available in the extension popup.

Block selected
Selected categories are hidden. Videos in every other resolved category remain visible.
Allow only selected
Only videos whose resolved YouTube category is selected are shown. Unknown cards stay covered while FilterTube checks their category, so unrelated videos should not flash briefly and disappear later.
This mode is independent
The category mode does not change the profile's normal Blocklist or Whitelist mode. For example, a Blocklist profile can still use Allow only Education and Gaming for categories.
Where it applies
FilterTube applies resolved categories to ordinary video cards, the current Watch video, and Watch recommendations. A Mix discovery card may use its seed video's category, but playlist and Mix queue rows are not treated as separate category-owned videos. Comments are never category-filter targets.
Why a card may load briefly
Home and Search responses often omit category. FilterTube checks only nearby cards through YouTube's structured Player response, reuses saved results, and limits requests to small batches. A short loading veil is expected on uncached cards; repeated “Category unavailable” cards are not normal.

Filter Videos By Spoken Language (Experimental)

Language Filters prefer the language linked to YouTube's default audio track. For captionless videos, strong script evidence in creator-supplied Player metadata can provide a fallback. Find this experimental card at the bottom of Content Controls, then turn it on to choose Block selected or Allow only selected and select languages from the visible pills. Turning the filter off collapses the picker but keeps your saved selection. Unknown-language videos remain visible, and YouTube Kids is not filtered by language yet. Main YouTube controls are also available in the popup.

What counts as the language?
FilterTube first uses YouTube's explicit original/default audio-format metadata, excluding auto-dubbed alternatives, then its audio/caption-track mapping. If those are absent, it can accept strong writing-system evidence from the title, description, and tags inside the same Player response—for example, dominant Russian Cyrillic text. It does not use the interface language, country, channel locale, or translated-subtitle menu.
Block selected
A resolved matching language is hidden. A video whose language is unavailable stays visible.
Allow only selected
A resolved nonmatching language is blocked. While language evidence is loading—or if it remains unavailable—the page stays usable instead of being blanked or pausing playback.
Why this does not double requests
FilterTube first reuses a Player response already loaded by YouTube. If a visible uncached card needs more information, category, language, description, dates, and identity needs are merged into one paced request for that video and then cached.
Current boundary
This control applies to Main YouTube. YouTube Kids does not show it until Kids responses provide equally reliable default-audio evidence. A dubbed video follows YouTube's selected default track.

Always Use Original Audio (Experimental)

This is a playback preference, not a language filter. Open Filters > Content Controls > Player and enable Always Use Original Audio (Experimental). On Main YouTube, FilterTube will prefer the creator's proven original track instead of an automatic dub.

What changes?
Only the audio track selected in the current player. Search results, recommendations, translated titles and descriptions, captions, and filtering rules do not change.
Does it make another request?
No. FilterTube reads the Player response YouTube already loaded, then uses YouTube's own in-page audio-track controls. There is no caption download, language lookup, or repeated network polling.
What if the original is unclear?
Playback continues normally. FilterTube does not guess from the title or channel and does not show a checking screen. It acts only when a non-auto-dubbed original/source track can be matched uniquely.
Current boundary
The experimental preference applies to Main YouTube Watch playback, including SPA navigation and playlist or autoplay transitions. YouTube Kids is excluded until its Player data exposes equally reliable original-track evidence.

Common Parent Questions

Where do I add a blocked word?
Open Filters, add the word under Keywords, then reload or navigate YouTube once. Use the Comment pill only if that word should also filter comments.
What does Exact mean?
Exact off: broader matching, so poop can also catch text like poops or pooping when YouTube exposes that text.
Exact on: stricter matching, so poop matches as its own word only.
What does Date mean on a keyword?
Use the Date pill only when that one word should apply to videos from a certain upload date. Example: Deltarune after 2025-06-10 blocks newer Deltarune videos but leaves older ones alone. If the Comment pill is also on, matching comments follow the video's upload date, not the comment's posted date. The Date pill should only stay active after you save a valid date.
Where do I block a channel?
Use the YouTube 3-dot menu or add the channel in Filters > Channels. A stable UC... channel ID is best, but handles and YouTube channel URLs are supported.
How do I limit YouTube time?
Open Accounts & Sync, create or choose a protected profile, then use Set limit. When time is finished, YouTube shows a calm FilterTube screen until the next reset or parent approval.
Can my child change these settings?
Not from a protected profile. A protected profile can watch within its rules, but it cannot change rules, PINs, trusted devices, viewing spaces, backups, or time limits without parent/account authority.
Why are there two PINs for Child Profile?
They do different jobs. The parent/account or Master PIN controls rules, time limits, viewing access, trusted devices, and backups.
The child/profile PIN only protects opening that profile, so siblings or any other user cannot casually switch into it. It never grants rule-editing power.
Can I edit child rules without touching the child device?
Yes. From the parent/account profile, open Accounts & Sync, choose the protected profile row, then select Edit Rules. FilterTube opens that child profile in parent-managed edit mode on your device. When the rules look right, send them to the verified child device.
How do I update their other device?
Start with Send Update while both devices are open. After the protected device saves the parent link, Pickup can let that verified device collect a signed parent update when it opens later. The device still checks the saved parent link before applying anything.
Where do imported lists go?
Use Settings > Rule list imports. Choose Main YouTube, YouTube Kids, or Both before applying. Import files can add channel and keyword rules only; they cannot change PINs, devices, profiles, time limits, or access.
What should I avoid touching at first?
Leave device Pickup, full-account sync, import/export, and advanced profile policy alone until basic blocking works. They are useful, but not required for day-one setup.

How FilterTube Works

Optional

FilterTube uses two hiding paths so rules keep working as YouTube changes pages.

When YouTube loads video data through JSON, FilterTube tries to remove blocked items before they appear.

YouTube reuses page pieces while you scroll and navigate. FilterTube checks visible cards again and hides anything that matches your rules.

How FilterTube Works

FilterTube uses a hybrid approach to hide content across YouTube:

Data interception (Zero-flash when possible)
When YouTube loads content via JSON, FilterTube removes blocked items before they render.
DOM fallback (Safety net)
For SPA navigation, hydration, and recycled DOM nodes, FilterTube scans the page and hides blocked elements.

Keywords

Advanced Profile and PIN Reference

Advanced
Profile types
  • Default (Master): Admin for full exports, profile management, and account policy.
  • Account: Independent profile; can manage protected profiles.
  • Protected profile: Private viewing profile with its own Main/Kids rules; rule editing and settings stay parent-managed.
  • Parent-managed protected editing: A parent/account profile can use a protected profile row’s Edit Rules action without switching into that protected profile.
Locks & PINs
  • Locked profiles disable toggles and auto-backup controls until unlocked.
  • Encrypted exports/backups need the profile’s PIN; Master unlock is required for admin actions.
  • Protected-profile PINs protect switching into that profile and can open receive-only Accounts & Sync; they do not grant parent/admin authority.
  • Parent/account or Master PIN controls rule edits, allowed viewing spaces, time limits, backups, trusted-link policy, and settings.
  • Parents can set or remove a protected profile’s switching PIN from the parent/account profile row after parent/account unlock.
  • Use Lock Admin Session in Security when you want temporary parent/admin unlocks to end immediately on this dashboard.
  • Opening receive-only Accounts & Sync with a protected-profile PIN does not unlock Dashboard, Filters, Kids Mode, Settings, or parent controls after you return to the viewing surface.
  • Unlock is per-session in both Popup and New Tab.
Auto-backup & actions
  • New profiles inherit the creator’s auto-backup mode/format/enable state.
  • Scheduling runs on profile creation and mode/format changes only if auto-backup is enabled for that profile.
  • Export scope toggle is disabled/forced to active-only for non-master; enabled for Master.
Where to change things
  • Popup: Quick toggle changes; respects locks/PINs; auto-backup controls visible when enabled.
  • New Tab: Full profile management (create/rename/delete, PIN set/remove), export/import, auto-backup mode/format.

Device Update Details

Advanced
Family Devices
Open this only when you want the detailed device-update model used by implementation and audit docs.
Advanced delivery
Home Pickup and Internet Pickup are optional setup paths for verified devices that cannot stay open for Send Update. They are not required for normal parent control.
Three simple ways to send updates
  • This profile: Best for your own second device. Pair, verify, send, and let the other device review the update.
  • Protected device: Best for parent/caregiver control. Pick the protected profile once, then save parent trust.
  • Full account: Use only for migration, reinstall recovery, or the wider account tree.
  • Protected receive-only: Protected profiles can join a parent code and receive updates, but cannot send, save trust policy, move backups, or unlock parent controls from that page.
  • The More options section is still there if you need to tune role, scope, or merge/replace manually.
How the pairing flow works
  • Pair: Create a 4-character code or QR on one device and join from the other.
  • Verify: Confirm the same safety phrase on both devices before sending anything.
  • Send: Share only the scope you want: active, main, kids, or full.
  • Simplest mental model: Pair, verify, send once, then save trust only if this protected device should receive future approved updates.
Quick start for parents
  • Choose Protected device on the parent device.
  • Connect once and confirm the same safety phrase.
  • Pick the protected profile in Profile to update on the parent side.
  • On the first managed connection, the protected device may still need one local unlock step to save the parent link for that profile.
  • After you choose Apply + Save Parent Link, later signed parent updates can reuse that target and policy instead of asking the protected user to reconfigure everything again.
What is private and what is not
  • The meeting service only helps both devices find each other. Think of it as a meeting place, not a place where your settings live.
  • After the secure handshake, your settings are meant to move directly from one device to the other.
  • FilterTube does not need a central sync account to read or store your Nanah settings traffic.
  • There is no product goal here around reading your synced rules or chasing user-count analytics from your private settings.
  • You should still trust only your own devices and confirm the same safety phrase before applying anything.
Device roles and trust
  • My other device: Best for one-off syncing between your own equal devices.
  • This device controls another profile: Use this on the parent/caregiver device that sends future protected-device updates.
  • This device receives protected updates: Use this on the protected profile or family device that should accept matching parent updates.
  • Saved trust: A trusted link remembers which parent can send which update. It is not an always-on live connection; if Pickup is set up, the protected device can collect a signed parent update when it opens later.
Managed links on the first connection
  • A first parent-to-protected-device session still asks the receiving device what to do with the first incoming update.
  • The protected device can apply once without saving trust, or apply and save a parent link for future updates.
  • Saving parent trust is what turns future parent policy into something precise and repeatable.
Allowed scopes inside parent trust
  • Each trusted parent link can allow one or more scopes: active, main, kids, or full.
  • The default scope and the merge/replace policy live on the trusted link itself, not only in the live session.
  • If an incoming managed update does not match the saved allowed scopes, FilterTube blocks it instead of applying the wrong scope.
  • Protected-device links can choose a target mode on the receiving device: Current active profile or Always this local profile.
  • The fixed target mode is the safe way to make B -> B work across devices without guessing by profile name.
PINs and encrypted backups
  • PIN checks stay local. Nanah can require the sender or receiver to unlock locally, but the PIN itself is not sent.
  • Protected-profile PIN and parent authority are separate. A protected-profile PIN can open receive-only sync for that profile, while parent/account PIN controls rule edits, backups, sync policy, and trusted links.
  • Encrypted backup is still the archive path. Nanah is the live device-to-device sync path.
  • Encrypted full-account backup can also carry trusted-device recovery data for same-device reinstall recovery, but normal/plain export does not.
  • Restoring trusted-device recovery data is explicit during encrypted import. It is not silently restored from ordinary backup files.
  • Parents can still keep stricter control by using PIN-locked profiles plus trusted parent links for protected devices.
Refresh, reconnect, and trusted links
  • A live Nanah session is not meant to survive a page refresh, browser restart, or tab close. Refresh ends the live pairing session.
  • Trusted links are saved locally so you do not lose the remembered relationship, but today you still start a fresh live session when reconnecting.
  • The trusted-device card now has a Start New Session shortcut that starts the next fresh session with the saved role/policy defaults.
  • Saved trust means a faster next Send Update session. If Internet Pickup is separately configured, a protected profile can check for signed parent updates when it opens without adding YouTube page background work.
  • If you try to reuse the same pairing code on the same active device session, FilterTube now blocks that locally instead of silently burning the code.
  • If no fixed target is saved on the managed replica link, non-full sync still writes into the receiver's current active profile at receive time.
  • If a managed replica link is saved with Always this local profile, future managed updates land in that pinned local profile even when some other profile is active on the receiving device.
What backups include today
  • Current Nanah trusted-link records are stored in local extension storage, not inside the normal FilterTube export/import payload.
  • Normal/plain backup restores your profiles and filters, but not the saved Nanah trust graph.
  • Encrypted full-account backup can include trusted-device recovery data, and import asks whether to restore it for same-device recovery.
  • That recovery path is intentionally explicit and should not be used to clone one device identity onto another device.
Master, account, and protected behavior
  • Default / Master: Owns full import/export, master policy, and the broadest account controls.
  • Independent account: Owns its own settings and can manage its own protected profiles, but does not gain authority over parallel accounts.
  • Protected profile: A private viewing surface with its own Main/Kids rules. The profile PIN protects switching into it, but parent/account PIN controls policy and rule edits.
  • Viewing spaces: A parent can set each protected profile to Kids only, Main only, or Main + Kids. New protected profiles start as Kids only.
  • Parent editing: Parent/account surfaces can edit a protected profile’s Main or Kids rule list directly from the protected profile row, so parents do not need to share the parent PIN.
  • Targeting today: Protected-device links should usually save a fixed local target so parent updates stay tied to that protected or family profile.
  • Parent-safe targeting: FilterTube blocks send-anyway paths from protected profiles when the other device has a different profile active. The intended parent flow is to save one parent trust link on the receiving protected profile and choose Always this local profile.
  • Parent managed: The normal protected-device preset saves a fixed target, allows matching signed parent updates while locked, and checks for later updates when the profile opens.
  • Ask first: A stricter option can require local approval/unlock before later parent updates apply.
  • Protected profiles do not expose broad backup/import/export/account-admin actions in Settings and cannot rename/delete profiles, mutate PIN policy, or edit trusted parent links from the protected surface.
Parent control without giving kids the PIN
  • Kids should not learn or type the parent PIN for normal managed updates.
  • The right model is local authorization on the protected device: trust the parent link once, then allow only the saved managed scopes and policies.
  • FilterTube keeps PIN values local. A trusted protected-device link can either let matching parent updates apply while locked or ask on this device first, and that permission is saved only on the protected device.
How devices meet
Nanah’s meeting service only helps two open devices exchange connection setup data. It does not read parent rules, PINs, or profile data. In the normal parent flow, open both devices, pair, verify the phrase, and use Send Update. Internet Pickup and Home Pickup are optional delivery tools for advanced setups; they still cannot apply anything unless the protected device already trusts that parent link. The underlying project is open here: github.com/varshneydevansh/nanah.
Nearby helper and Home Pickup
The optional nearby helper lets you select an opted-in FilterTube device on the same network, then returns to normal code/phrase verification. Home Pickup is different: it is an advanced waiting-update service for already verified protected devices. Neither path trusts every device on the network.
Internet Pickup
Internet Pickup is for a verified protected device that may open later or away from the parent device. It needs a trusted online pickup setup that stores unreadable signed updates until the protected device checks in. The service cannot read rules, approve itself, change PINs, or pick a profile; the protected device still validates the saved parent link before applying anything.

Blocklist, Whitelist, and exceptions

Choose the default policy
Blocklist keeps YouTube visible except for things you block. Whitelist hides by default and shows only matching allowed channels or keywords.
Add an exception without changing modes

The full Main and YouTube Kids filter pages each have a list browser. Open Blocked rules or Allowed rules to view and edit that saved collection. This only changes the list you are looking at; it does not switch Blocklist / Whitelist mode, and Kids rules remain independent from Main:

  1. Choose Blocked to add a normal block rule.
  2. Put a favorite channel or useful keyword in Allowed rules.
  3. The popup follows the active global mode for quick additions; advanced exception editing stays in the full Filters page.
  4. In Blocklist mode, an allowed channel can rescue its videos from a broader blocked keyword.
  5. When you switch from Blocklist to Whitelist with an empty Allowed list, FilterTube can copy your current blocked rules into Allowed rules to get started. The original Blocked rules are kept.
  6. Switching back to Blocklist never transfers or deletes either list. Bootstrap copies do not cancel their original blocked rules in Blocklist mode; Allowed rules you add yourself still work as normal exceptions.
What stays visible?

In Whitelist mode, FilterTube:

  • hides by default,
  • shows videos from allowed channels,
  • shows videos that match allowed keyword rules,
  • keeps normal watch pages and playlists usable for allowed content.
Subscriptions page stays reachable
Your subscriptions management page stays visible so you can still review and manage channels without locking yourself out.
Creator and channel pages
Opening a blocked channel directly redirects back to YouTube Home. Creator and channel cards still follow the same allow-only idea: if FilterTube cannot confirm a card is allowed, it chooses the safer hidden state.
Direct links and embedded players
A direct Watch, Shorts, playlist/autoplay, or embedded YouTube player cannot bypass your rules. In a playlist or autoplay queue, FilterTube pauses a blocked current video and automatically moves to the next allowed video when one is available. It reuses the loaded Player response and visible Watch description first. Block selected does not hold normal playback merely because a complete description is still unavailable; Allow only selected waits when identity is required to prove the video is allowed.
Links on Google and other websites
FilterTube does not read or remove ordinary YouTube links on Google Search or other websites. When the link opens YouTube, the direct-access gate applies there. Embedded YouTube and privacy-enhanced YouTube players are covered inside their player frames. Hiding links on external pages would be a separate opt-in feature because it requires permission to read and modify those websites.
Which rule wins?
A video rule is more specific than a channel rule, and a channel rule is more specific than a keyword. When equally specific block and allow rules both match, allow wins. Core controls such as Hide Shorts and Hide All Comments still win over ordinary exceptions.
Moving from BlockTube
Choose the BlockTube JSON as a backup import. FilterTube first shows counts for channels, video IDs, title rules, comment rules, regex rules, mapped settings, and unsupported fields. Large imports are capacity-checked and applied as a transaction: if any required write fails, FilterTube restores the previous state instead of showing false success. A successful import is read back and produces an apply receipt. Imported JavaScript stays inactive, BlockTube's UI password is never used as a FilterTube PIN, and the FilterTube theme is preserved. You can download the migration report before importing.

Profiles, PINs, and Protected Profiles

What is a protected profile?
A protected profile is a viewing space for a child, family member, or anyone who should watch within rules but not change those rules. It can have its own Main YouTube rules, Kids rules, PIN, and time limit.
Two PINs: control vs switching
Parent/account or Master unlock is the control PIN. It edits rules, time limits, backups, trusted devices, and Main/Kids access. The protected profile PIN is only a switching PIN. It helps stop siblings or any other user from opening each other's profiles, but it cannot edit policy or remove parent controls.
Admin unlock safety
Parent/admin unlock is temporary. Sensitive actions can ask for the PIN again, Lock Admin Session ends the current dashboard unlock immediately, and repeated wrong PIN attempts are delayed and written to protected history so the parent can notice tampering without exposing the PIN.
Who sets a protected profile PIN
A parent/account profile can set, change, or remove a protected profile's switching PIN from the protected profile row after parent/account unlock. The protected user cannot use that PIN to remove parent controls.
Where parents edit protected rules
Open Accounts & Sync from the parent/account profile and use the protected profile row's Edit Rules button. A banner stays visible while you edit that protected profile's Dashboard, Filters, Kids Mode, Settings, and Accounts & Sync surfaces.
Allowed viewing spaces
Each profile can be set to Kids only, Main only, or Main + Kids. This supports younger kids on YouTube Kids and teenagers on supervised Main YouTube without letting either edit policy.
Family Controls
Use the parent/account profile to create a protected profile, set Main/Kids access, set daily YouTube time, edit rules, and send updates to a verified device. The protected profile can watch within those rules, but cannot change parent controls from its own surface.
Import a rule list for protected profiles
From the parent/account profile, open a protected profile row and choose Edit Rules. Then use Settings > Import / Export > Rule list imports and choose Main, Kids, or Both. Imported files only add channel/keyword rules; they cannot change PINs, trusted devices, viewing spaces, or sync targets. After import, use the protected profile row to send the updated policy to a verified device.
When time is finished
Daily time is counted separately for every profile that has a limit—not as one shared browser allowance. The popup shows the active profile's remaining time. YouTube and its controls stay behind a full-page FilterTube pause screen with the serene landscape only while the active profile is exhausted. A protected profile can wait for its daily reset, request more time for parent review, or switch through the normal PIN flow to another independently governed profile. Account profiles use their own policy and remaining balance, and active playback continues counting even when another extension or developer window temporarily has focus.
Self-Control Session vs daily YouTube time
A daily limit controls how long a profile can use YouTube. A Self-Control Session, started from Settings, instead enables and freezes the active profile's current filters and settings for a countdown you choose. During that session, profile switching, filtering pause, rule edits, mode changes, and imports are blocked. It survives a browser restart, shows its countdown in the popup and dashboard, and has no FilterTube cancel button. The browser owner can still disable or uninstall an extension unless the browser or device is externally managed.
Remote updates in plain words
Normal parent control is Send Update: open parent and protected devices, pair, verify the phrase, then send the selected profile update. Saved trust remembers the verified parent/protected-device relationship and target profile for the next live session. Home Pickup covers explicitly configured home/school pickup, and Internet Pickup covers away or opens-later devices through a trusted online pickup setup. These paths are optional, are not required for ordinary parent control, do not scan Wi-Fi for authority, and never let a protected profile edit its own rules.

YouTube Kids

Keep Kids rules separate
YouTube Kids has its own rules in FilterTube. Use Kids Mode when you want a different list for younger children.
Parent changes stay parent-side
FilterTube avoids adding rule-changing shortcut buttons inside YouTube Kids because a protected user could tap them. Change Kids rules from FilterTube or YouTube Kids parent controls instead.
YouTube blocks and FilterTube blocks are separate
If you block something inside YouTube Kids itself, YouTube manages that block. FilterTube keeps its own Kids list so you can back it up, edit it, and sync it separately.
If a Kids channel still looks blocked

There may be two lists involved:

  • FilterTube's Kids list.
  • YouTube Kids' own parent-account block list.
  • If removing a rule from FilterTube does not bring the channel back, check YouTube's official unblock steps: Unblock channels from YouTube using your linked parent account.
YouTube Kids parent account
Some YouTube Kids actions still require YouTube's linked parent account. FilterTube adds extra local rules; it does not replace YouTube's parent-account controls. See YouTube Kids Help Center for YouTube-owned controls.
Using Kids rules on Main YouTube
  • Kids block rules can apply on Main YouTube when Main is also in Blocklist mode.
  • Kids allow rules can apply on Main YouTube when Main is also in Whitelist mode.
  • FilterTube does not flip a Kids allow-list into a Main blocklist, or a Kids blocklist into a Main allow-list.
  • Rows copied from Kids Mode are labeled so parents can see where they came from.

Troubleshooting

"Failed to fetch" while blocking
If FilterTube already knows the channel UC ID, it can still persist the block even if fetching the logo/name fails. Try reloading if the UI doesn't update immediately.
Blocked channel still appears
YouTube sometimes reuses DOM nodes during SPA navigation. FilterTube re-scans and clears stale cached metadata, but a hard refresh can help confirm persistence.
Subscribed-channel import
Imported subscriptions are now captured more defensively across browsers. If the first pass looks incomplete, reopen the subscribed channels surface and let FilterTube re-capture the page data before trying again.
