# How to port Android to the extension

The Android phone app is the source of truth for features. The browser extension follows it
commit by commit, and the port ledger records every step so the extension can't drift from Android
without anyone noticing. This is the extension's copy of the app repository's iOS ledger
(`FilterTubeApp docs/parity/`), with the same columns, statuses and areas.

| File | What it is |
|---|---|
| [`PORT_LEDGER.tsv`](PORT_LEDGER.tsv) | One row per Android commit since the sync point. This is the file you edit. |
| [`PORT_LEDGER.md`](PORT_LEDGER.md) | A readable view of the TSV, generated by `render`. Never edit it by hand. |
| [`FILE_MAP.tsv`](FILE_MAP.tsv) | Each Android file changed since the sync point, mapped to the extension file(s) that carry it, or `n/a` / `none (gap)`. |
| [`tools/parity/ledger.mjs`](../../tools/parity/ledger.mjs) | `check`, `add`, `render`, `files` and `shared` (Node, no dependencies). |
| [`tools/parity/derive-file-map.mjs`](../../tools/parity/derive-file-map.mjs) | Regenerates FILE_MAP. It keeps rows marked `manual`. |

Android lives in the app repository, not here. The tools find it at `FT_ANDROID_REPO` (or
`--android-repo <path>`), else `~/FilterTubeWorktrees/study-3.6.2`, else `../FilterTubeApp`. The
sync point is Android `ec9d91080` (Release Android 3.6.1). A commit is **tracked** if it comes after
the sync point on `feature/android-3.6.2-study` (set `FT_ANDROID_REF` or `--android-ref` for another
ref) and touches `apps/android/`. The tools only read the app repository; they never write to it.

## The rules

1. **Every Android commit gets a ledger row.** Run `node tools/parity/ledger.mjs add <sha>` for each
   new Android commit. The row is prefilled from git (date, subject, guessed area, Android files)
   with a guessed status: `n/a` for TV, Sangeet, downloads, local media and debug-only commits,
   `todo` otherwise. `check` exits with 1 while any tracked commit has no row or a row is malformed.
2. **Every extension port commit cites `Ports Android <sha> (files)`.** Name the Android commit and
   the Kotlin or resource files you read, for example
   `Ports Android e64d74490 (StudyMerge.kt, StudyMergeTest.kt)`. In the same commit, set the row's
   `status`, `ext_shas` (this commit's SHA goes in a follow-up ledger commit, since a commit can't
   name itself) and `ext_files`.
3. **Port from Android's code, never from screenshots.** Read the Kotlin and the XML: the conditions
   and the order of checks, dp and sp values (1 dp = 1 CSS px), colours from `BrandPalette` and
   `CountryAccent`-style tables, string keys and plurals, durations and easing. Screenshots only
   check the finished port side by side. Keep Android's names in a comment (`Android StudyMerge`) so
   FILE_MAP's `cited` match finds the pair.
4. **Android tests become extension tests.** If the Android commit adds or changes a test,
   `FooTest.kt` becomes cases in `tests/runtime/app-parity-*.test.mjs` with the same inputs and
   expectations. `ledger.mjs files <sha>` names the file to write. A port without its tests is
   `partial`.
5. **Shared code stays identical.** The app bundles this repository's files (the app's
   `tools/sync-runtime-from-extension.mjs` and `tools/runtime-sync-manifest.json`): the runtime
   bundle `assets/filtertube_runtime_full.js` (one section per `js/` file), the Nanah files under
   `assets/filtertube_nanah/`, `assets/extension_shell/data/release_notes.json` and
   `assets/study/packs-v1.json`. `ledger.mjs check` (or `shared`) compares every one with the
   extension's `HEAD` and says, for each that differs, whether Android has an older extension
   version (the extension is ahead and the app needs `npm run sync:native-runtime`) or a copy no
   extension version matches (Android changed it). Never fix shared logic only on the Android side:
   port it here, then sync.
6. **Statuses mean exactly this:**
   - `ported`: the extension does what the Android commit does, and `ext_shas` names the commits.
   - `partial`: some of it is here. `reason` says what's missing ("not traced" means nobody has
     checked that part yet).
   - `todo`: nothing yet.
   - `n/a`: nothing to port, and `reason` says why. A browser extension has no own player, TV,
     Sangeet player, local media, downloads, Android widgets, app icon or launch screen, no native
     viewer (it filters the site's own pages) and no Android plumbing (threads, insets, WebView
     host, deep links, logcat). Android resource moves are `n/a` because the extension's words
     already live in `data/ui_locales`. Docs-only and Android-test-only commits are `n/a`.

   What usually applies: filters and rules, content controls, Study, Family and Ask a parent,
   profiles and PINs, sync formats and Nanah, the Controls look, mascots, doodles and sounds, copy
   and terminology, the Support sheet and What's new.
7. **Verify before you mark something ported.** Read the extension diff against the Android diff;
   a matching subject is not enough. Say what you checked in `reason`.

## A port, step by step

```sh
node tools/parity/ledger.mjs check            # rows missing, open rows by area, % ported, shared drift
node tools/parity/ledger.mjs add <sha>...     # new Android commits -> rows
node tools/parity/ledger.mjs files <sha>      # the extension files (and test) to touch for one commit
# ... port here, commit with "Ports Android <sha> (files)" ...
# edit PORT_LEDGER.tsv: status, ext_shas, ext_files, reason
node tools/parity/ledger.mjs render           # refresh PORT_LEDGER.md
node --test tools/parity/ledger.test.mjs      # also part of npm test (smoke lane)
```

Close `todo` and `partial` rows in the order `check` lists them: by area (brand, viewer, watch,
study, kids, profiles and family, controls, ...), then `todo` before `partial`, `feat` before `fix`,
newest first.

## TSV format

Tab-separated with one header line. Lists inside a cell use `;` for files and `,` for SHAs. Cells
can't contain tabs or newlines. Translated resources are collapsed, so
`res/values-*/strings_study.xml (37)` stands for 37 locale files.

| Column | Meaning |
|---|---|
| `android_sha` | 9-character Android SHA (app repository) |
| `date`, `subject` | from git |
| `area` | `brand-visual`, `home-viewer`, `watch`, `study`, `kids`, `profiles-family`, `settings-controls`, `search`, `music`, `channel-playlist`, `subs-you`, `nearby-sync`, `support`, `strings`, `tablet-tv`, `infra`, `release`, `docs-test`. This order is also the user-visibility rank `check` uses. |
| `status` | `ported`, `partial`, `todo` or `n/a` |
| `ext_shas` | the extension commits that port it |
| `reason` | required for `partial` and `n/a`; a short note otherwise |
| `android_files` / `ext_files` | the files each side changed (the extension's without translated catalogs, docs and images) |

FILE_MAP columns: `android_file`, `kind` (kotlin, test, layout, values, drawable, raw, font, asset,
app-icon, other), `ext_files`, `match` and `note`. The `match` values, strongest first:

- `manual`: written by hand; `derive-file-map.mjs` keeps it
- `shared`: the app bundles this extension file (rule 5)
- `cited`: an extension source line names the Kotlin type
- `audit`: [`EXTENSION_ANDROID_PARITY_AUDIT_2026-11-16.md`](../design/EXTENSION_ANDROID_PARITY_AUDIT_2026-11-16.md) pairs them
- `known`: paired by hand in `derive-file-map.mjs` (`KNOWN_KOTLIN`); a hint, check the file
- `assets`: the same art, sound, icon or font (`study_x.webp` → `assets/images/mascots/x.webp`,
  `ui_x.ogg` → `assets/sounds/x.ogg`, `icon_x.xml` → `assets/icons/crayon/x.svg`)
- `strings`: a strings file; its English lives in `data/ui_locales/en.json`
- `n/a`, `none`: nothing to port, or a gap

## Seeding (2026-11-17)

The first ledger was built from
[`EXTENSION_ANDROID_PARITY_AUDIT_2026-11-16.md`](../design/EXTENSION_ANDROID_PARITY_AUDIT_2026-11-16.md)
(passes 3 to 5, feature by feature) and the extension's commit messages on `feature/ext-parity`
(`6770e0ab`), which mostly name the Android types they port rather than SHAs. These ported claims
were checked against the code: `495ed51ee` (the ask's kind comes from the typed decision,
`channelAnswerable` only for a channel rule), `7cdaeeb9a` and `184da9e82` (every mascot frame is
byte-identical to Android's `study_*` drawables), `648a59238` (all 13 sounds byte-identical),
`bd6b6adb4` and `79f10fec8` (`packs-v1.json` identical), `6faa445b0` (the idle wake listens to the
same input kinds with a 120 s budget), `8dfad6d2d` (the support copy's wording) and `fad68cd40`
(the extension commit cites it). The check also found two real gaps, ported right after:
`e64d74490` and the merge half of `ce156df15` (`mergeStudy` dropped a parent's "Pack channels
only" and let a sync change a parent's round and break lengths).
